# TruLens 单环境仪表盘依赖调整设计

## 目标

取消 TruLens Dashboard 的独立 Conda 环境，将 Dashboard、TruLens 评测和应用依赖统一安装到 `yyy-rag` 环境，同时保持依赖解析一致且不修改 `src/` 生产代码。

## 根因

`trulens-dashboard==2.14.0` 依赖 `psutil>=5.9,<6`，而当前 `unstructured==0.27.5` 依赖 `psutil>=7.2.2,<8`。两者不能在同一 Python 环境中由 pip 正常解析。不能通过 `--no-deps` 或强制覆盖 `psutil` 规避，因为会留下不满足声明约束的环境。

## 方案

1. 选择一个经元数据验证、依赖 `psutil<6` 的 `unstructured` 历史版本。
2. 将该 `unstructured` 版本与 `trulens-dashboard==2.14.0`、`psycopg[binary]` 固定在同一 `requirements-evaluation.txt`。
3. 删除 Dashboard 专用依赖文件和独立环境启动说明。
4. `run_trulens_dashboard.py` 仍在主环境中运行，并连接既有 PostgreSQL `trulens` 数据库。
5. 执行依赖一致性、文档解析模块导入、TruLens 单测、真实 PostgreSQL 记录读取以及 Dashboard 数据库解析验证。

## 风险与约束

- 降级 `unstructured` 可能改变其文档解析行为，因此必须验证项目使用的 LlamaIndex 文档加载回退路径至少仍能导入和执行现有测试。
- 仅在依赖元数据满足 `psutil<6` 时采纳候选版本。
- 不更改 `src/`，不重新执行 MinerU 或 embedding 生产逻辑以外的无关重构。
- PostgreSQL 评测数据继续保留，不迁移数据库。

## 验收标准

1. `yyy-rag` 环境执行 `pip check` 无冲突。
2. 主环境已安装 `trulens-dashboard==2.14.0`，且 `unstructured` 与 `psutil` 约束同时满足。
3. Dashboard 使用主环境的 Python 解析到 PostgreSQL `trulens` 数据库。
4. `test/evaluation` 单测与文档解析相关现有测试通过。
5. `src/` 无改动。
