# 文档切分策略可选化设计

## 文档状态

- 状态：已确认设计，待实施
- 设计日期：2026-09-15
- 实现范围：后端优先；上传 API 接收策略，异步导入按策略执行
- Git 约束：不执行 Git 提交，提交权由用户决定

## 1. 背景与问题

当前离线导入链路的切分行为不统一：MinerU 成功时调用 `_split_markdown()`，按段落合并并对超长段落做字符窗口切分；MinerU 回退到 LlamaIndex 时使用 `SentenceSplitter`。上传接口不接收切分方式，文档元数据也不记录实际策略，后台异步任务无法追溯用户的切分选择。

本次将切分策略显式化，用户在上传时选择切分方式，后台任务读取文档持久化的策略执行索引。用户只选择方法，不输入任意切分参数；`chunk_size`、`overlap` 和语义阈值由后端统一配置，避免文档之间的策略参数混乱，也避免参数修改后无法追溯旧索引。

## 2. 目标

1. 提供 `recursive`、`sliding_window`、`semantic` 三种切分策略。
2. 将现有 `_split_markdown()` 替换为标准递归切分实现。
3. 为所有文档解析路径统一使用用户选定的切分策略。
4. 上传接口新增 `chunk_strategy` multipart 字段，默认 `recursive`。
5. 在 `documents` 表中保存用户选择的 `chunk_strategy`，供异步任务使用和文档查询展示。
6. 对已有文档迁移填充默认策略 `recursive`，不重新索引旧文档。
7. 不执行真实 Embedding、Milvus、MinIO、MinerU 或 LLM 调用作为自动测试的一部分。

## 3. 非目标

- 不允许普通用户输入任意 `chunk_size`、`overlap` 或语义阈值。
- 不新增文档重新索引接口或历史文档自动重建索引。
- 不改变 Milvus collection schema、文档 ID、分块 ID 或检索过滤逻辑。
- 不改变当前 MinerU 页码未知时写入 `0` 的行为。
- 不在本次修改前端上传界面；前端后续可将同名字段传入已有上传接口。
- 不使用 LLM 进行语义切分，避免额外生成模型成本和不可重复输出。

## 4. 策略定义

### 4.1 策略标识

```python
ChunkStrategy = Literal["recursive", "sliding_window", "semantic"]
```

- `recursive`：默认值，标准递归字符切分；
- `sliding_window`：固定长度字符滑动窗口；
- `semantic`：基于相邻文本单元 Embedding 余弦相似度的切分。

### 4.2 递归切分

使用已安装的 `langchain_text_splitters.RecursiveCharacterTextSplitter`。中文/Markdown 优先分隔符固定为：

```python
["\n\n", "\n", "。", "！", "？", "；", "，", " ", ""]
```

切分器使用全局 `CHUNK_SIZE`、`CHUNK_OVERLAP`。优先在段落、换行、句末和中文标点边界切分；单元仍过长时逐步降级为更细分隔符，最后按字符切分。

### 4.3 滑动窗口切分

按字符窗口生成 chunks：

```text
窗口大小 = CHUNK_SIZE
下一窗口起点 = 上一窗口结束位置 - CHUNK_OVERLAP
```

当最后一个窗口已经被前一窗口完整覆盖时停止，避免产生冗余尾块。`CHUNK_OVERLAP` 对该策略始终生效。

### 4.4 语义切分

语义切分使用现有 `Embeddings` 模型，不使用 LLM：

```text
文本源单元（段落；无段落时按中文句末符号拆分）
  -> 批量调用 aembed_documents
  -> 计算相邻单元余弦相似度
  -> 相似度低于阈值时形成语义边界
  -> 同时以 CHUNK_SIZE 作为上限聚合单元
  -> 单个过长单元回退到递归切分
```

新增后端统一配置：

```env
SEMANTIC_SIMILARITY_THRESHOLD=0.65
```

相邻文本单元相似度小于该值时断开。语义 chunk 不额外复制固定 overlap，以免破坏语义边界；它会比递归和滑动窗口多进行一次候选单元 Embedding，再对最终 chunk 进行索引 Embedding，因此导入更慢且可能增加 Embedding 成本。

## 5. 统一导入链路

所有策略在解析后统一执行，策略不再由 MinerU / LlamaIndex 路径隐式决定：

```text
上传 chunk_strategy
  -> PostgreSQL documents.chunk_strategy
  -> BackgroundTasks 认领导入任务
  -> 下载原文件
  -> MinerU Markdown 或 LlamaIndex 分页文本
  -> build_source_segments(text, page_number)
  -> split_source_segments(chunk_strategy)
  -> 最终 chunk 与 page_number
  -> 索引 Embedding
  -> Milvus 写入
```

`SourceSegment` 是内部结构，至少包含：

```python
text: str
page_number: int
```

MinerU 解析文本没有当前可用的页码映射，因此所有源单元页码为 `0`。LlamaIndex 路径从 `document.metadata['page_label']` 转为整数页码；无效或缺失值回退为 `0`。切分在单个 `SourceSegment` 内进行，不跨不同页码的源单元合并，从而保持现有页码语义。

## 6. API 与数据模型

### 6.1 上传 API

现有接口扩展为：

```text
POST /api/v1/knowledge-bases/{knowledge_base_id}/documents
Content-Type: multipart/form-data

file             必填
category         可选，默认 default
chunk_strategy   可选，默认 recursive
```

FastAPI 路由将 `chunk_strategy` 声明为受限 Literal。未知策略由请求校验返回 `422`，不会创建 MinIO 对象、文档或导入任务。

### 6.2 文档模型

`documents` 表新增：

```text
chunk_strategy VARCHAR(30) NOT NULL DEFAULT 'recursive'
```

SQLAlchemy `Document`、`DocumentResponse`、文档列表和文档详情都返回该字段。创建文档时保存上传请求选择，后台任务通过已保存的 `document.chunk_strategy` 调用 `ingest_file()`。

### 6.3 数据库迁移

新增 Alembic migration：

1. 为 `documents` 添加非空 `chunk_strategy` 列，服务端默认值为 `recursive`；
2. 为列增加中文注释“文档导入时使用的文本切分策略”；
3. 降级时删除该列。

旧文档在 migration 后显示和使用 `recursive`，但不会触发自动重新导入；Milvus 中已有向量保持不变。

## 8. 配置

保留：

```env
CHUNK_SIZE=512
CHUNK_OVERLAP=64
```

新增：

```env
SEMANTIC_SIMILARITY_THRESHOLD=0.65
```

参数由环境变量统一配置：

- `CHUNK_SIZE`：递归、滑动和语义策略的最大 chunk 字符数；
- `CHUNK_OVERLAP`：递归和滑动窗口的重叠字符数；
- `SEMANTIC_SIMILARITY_THRESHOLD`：语义策略中相邻单元的最小相似度阈值。

普通上传用户只选择策略。修改配置仅影响之后新建的导入任务；若需让已有文档采用新策略或新参数，应在后续通过重新上传或重新索引功能完成。

## 9. 错误处理

- 上传传入未知策略：FastAPI 返回 `422`；
- 策略在后台导入时出现异常：沿用当前任务失败机制，将错误信息写入文档和任务；
- 语义切分 Embedding 调用失败：整个导入任务标记为 `failed`，不静默降级为其他策略，防止用户选择和实际索引方式不一致；
- `CHUNK_OVERLAP >= CHUNK_SIZE`：滑动窗口内部使用最小步长 `1` 避免死循环；配置应由部署者修正；
- 空文本：返回空 chunks，导入任务沿用现有无内容处理；
- 单个语义源单元大于上限：仅对该单元回退递归切分，不改变文档整体选择的策略记录。

## 10. 测试与验收

### 10.1 纯函数切分测试

1. 递归切分：中文段落/句子边界优先，所有 chunk 长度不超过 `chunk_size`；
2. 滑动窗口：相邻窗口重叠为 `overlap`，末尾不创建完全重复的窗口；
3. 语义切分：使用确定的假 Embedding，在低相似度边界断开；
4. 语义切分：过长源单元回退递归切分；
5. 页码：同一源单元切出的 chunks 保持源页码，切分不跨页合并。

### 10.2 API 与任务测试

1. 上传不传 `chunk_strategy` 时使用 `recursive`；
2. 上传传入三种合法策略时保存对应值；
3. 未知策略返回 `422`；
4. `create_document()` 保存策略；
5. `run_ingestion_task()` 将策略传给 `ingest_file()`；
6. `DocumentResponse` 和 `Document` 列集合包含 `chunk_strategy`。

### 10.3 验收标准

- 三种策略均可通过上传 API 选择；
- 异步任务按持久化策略执行；
- 文档详情可查看策略；
- 旧上传客户端不传字段时仍能完成导入，默认使用递归策略；
- 直接相关的单元测试、Python 编译和 migration 模型检查通过；
- 不执行 Git 提交。

## 11. 设计自检

- 用户选择的是策略而不是任意参数，兼顾可用性和可维护性；
- 语义切分成本和非 overlap 行为已明确；
- 所有解析路径统一进入同一策略分发器；
- 异步任务通过数据库字段而非 HTTP 临时状态获取策略；
- 旧文档和旧客户端具有明确的默认兼容行为；
- 文档仅使用项目相对路径，不包含用户电脑绝对路径。
