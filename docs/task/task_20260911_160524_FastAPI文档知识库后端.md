# FastAPI 文档知识库后端实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，按任务逐项实现。每个任务都必须先写失败测试，再实现最小代码，最后运行该任务的验证命令。

**目标：** 在现有 RAG 项目中增加使用 PostgreSQL `rag`、MinIO 和 Milvus `knowledge_docs_v2` 的 FastAPI 文档知识库后端，并保持知识库级检索隔离。

**架构：** 新增 `src/api`、`src/db` 和 `src/services`，通过显式业务校验代替数据库外键。文档上传在 PostgreSQL 中创建 `pending` 文档和任务后使用 FastAPI `BackgroundTasks` 执行；worker 通过文档行锁保护任务认领、导入和删除并发。现有 `src/index/doc_ingestion.py` 和 `src/query/doc_rag.py` 只做必要的显式 ID 与 Milvus 过滤改造。

**技术栈：** FastAPI、Pydantic、SQLAlchemy 2.x、psycopg 3、Alembic、MinIO Python SDK、pymilvus、现有 LlamaIndex/Embedding/LLM/Reranker。

**规格文档：** `docs/spec/spec_20260911_160524_FastAPI文档知识库后端.md`

## 全局约束

- 生产业务数据库只能使用 `DATABASE_URL=postgresql+psycopg://rag:rag@localhost:5432/rag`，不能回退到 `TRULENS_DATABASE_URL`。
- `knowledge_bases`、`documents`、`ingestion_tasks` 不创建任何数据库级外键，不使用 `ForeignKey` 或 `ON DELETE CASCADE`。
- 所有业务 ID 使用 Python `uuid.uuid4()` 生成的 UUID4；文档 ID 必须贯穿 PostgreSQL、MinIO、Milvus 和 API。
- 所有三张业务表及每一个字段都必须通过 Alembic/SQL `COMMENT ON` 写入中文注释。
- 生产 Milvus collection 固定为 `knowledge_docs_v2`；不得让新 API 读写旧 `knowledge_docs`。
- Chat 检索必须传递 `knowledge_base_id` 过滤条件；文档删除必须同时使用 `knowledge_base_id` 和 `doc_id` 过滤条件。
- 知识库删除与文档创建必须锁定同一条知识库行；任务认领与文档删除必须锁定文档行。
- `pending` 或 `processing` 文档返回 409，不允许删除。
- 重要模块、类、函数和并发协议必须添加中文注释文本块；不做与本需求无关的重构。
- 大文件必须分段写入；不执行 Git 提交，提交权由用户决定。

```python
    rerank_top_k: int = Field(default=5, gt=0)
    use_hyde: bool = True

    @model_validator(mode="after")
    def validate_rerank_limit(self):
        if self.rerank_top_k > self.top_k:
            raise ValueError("rerank_top_k 不能大于 top_k")
        return self
```

使用 `ConfigDict(from_attributes=True)` 让数据库模型转换为响应模型。列表响应包含 `items`、`total`、`skip`、`limit`。`DocumentResponse` 包含 `id`、`knowledge_base_id`、`original_name`、`object_key`、`content_type`、`file_size`、`doc_type`、`category`、`status`、`chunk_count`、`error_message`、`created_at`、`updated_at` 和最新任务状态字段；不返回 MinIO 密钥或内部异常堆栈。
