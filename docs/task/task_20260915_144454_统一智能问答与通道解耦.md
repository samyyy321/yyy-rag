# 统一智能问答与通道解耦实施任务

> **For agentic workers:** 使用 `superpowers:executing-plans` 在当前会话逐任务执行。所有步骤使用复选框跟踪，不开启子代理。

**目标：** 将聊天从知识库管理页移至统一智能问答页面，使 document、graph、sql 通道可单选或多选，并仅在 document 被选择时要求知识库。

**架构：** 后端将 `knowledge_base_id` 调整为条件必填，document 通道独占知识库校验；GraphRAG/NL2SQL 可独立运行。前端保留一个 `ChatPage`，由顶层 `App` 在知识库管理和智能问答之间切换；ChatPage 按已选通道决定是否展示知识库选择器，并沿用既有 SSE 流式请求。

**技术栈：** FastAPI、Pydantic、React、TypeScript、TanStack Query、Vitest、React Testing Library。

**规格：** `docs/spec/spec_20260915_144238_统一智能问答与通道解耦.md`

## 全局约束

- [x] 仅支持 `document`、`graph`、`sql` 三个显式通道；不实现自动路由。
- [x] 未传 `channels` 时维持 `['document']` 默认行为和现有 API 路径。
- [x] `document` 被选择时必须提供且校验知识库；不包含 `document` 时不得访问知识库表。
- [x] 统一聊天页面是唯一聊天入口；知识库管理页不展示聊天入口。
- [x] 前端至少选择一个通道；无通道或 document 未选知识库时禁用发送。
- [x] 保留 SSE 流式文本追加、角色、检索数量、重排数量和 HyDE 设置。
- [x] 不引入 React Router、组件库或额外全局状态库。
- [x] 新增逻辑先写失败测试，再做最小实现；只运行本次直接相关测试。
- [x] Python 命令使用 `conda run --no-capture-output -n yyy-rag python ...`。
- [x] 不启动真实 PostgreSQL、Neo4j、Milvus、LLM 或初始化脚本，不产生业务测试数据和模型调用成本。
- [x] 不执行 Git 提交、推送或重置；每完成一个顶级任务更新本文件状态。
