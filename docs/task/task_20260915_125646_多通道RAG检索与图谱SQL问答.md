# 多通道 RAG 检索与图谱 SQL 问答实施任务

> **For agentic workers:** 按任务顺序执行；新增业务逻辑先写失败测试，再实现最小代码。任务状态使用复选框维护。

**目标：** 在现有文档 RAG 上新增 GraphRAG、NL2SQL、单通道与 `asyncio.gather()` 多通道融合，并提供可重复执行的 PostgreSQL/Neo4j 演示初始化脚本。

**架构：** `channels` 决定执行的文档、图谱和 SQL 通道。单通道使用对应回答提示词；多通道并行获取证据后由融合提示词生成答案。图谱和 SQL 查询均采用只读白名单校验，并在完整通道失败时最多重试一次。

**技术栈：** FastAPI、Pydantic、SQLAlchemy、psycopg、Neo4j Python Driver、LangChain Chat Model、asyncio、pytest。

**设计依据：** `docs/spec/spec_20260915_125646_多通道RAG检索与图谱SQL问答.md`

## 全局约束

- [x] 仅实现 `document`、`graph`、`sql` 三个显式通道；不实现自动路由。
- [x] `channels` 省略时保持原文档 RAG 行为。
- [x] 多通道仅对调用方已选通道使用 `asyncio.gather()`；一个通道失败不能阻塞其他通道。
- [x] NL2SQL 只允许五张演示运营表和单条 `SELECT`，强制 LIMIT 不超过 100。
- [x] Cypher 只允许 `MATCH`/`OPTIONAL MATCH` 只读查询，强制 LIMIT 不超过 20。
- [x] GraphRAG 和 NL2SQL 每次请求最多进行两次完整尝试，不加复杂退避策略。
- [x] 所有重要模块、类和函数添加中文文档注释；重要限制逻辑添加中文注释。
- [x] 图谱演示数据必须标注为仅验证流程，不能作为医疗依据。
- [x] Python 命令在 Conda `yyy-rag` 环境执行；使用 `conda run --no-capture-output -n yyy-rag python ...` 规避当前终端编码回显问题。
- [x] 测试使用最小模拟对象，不调用真实 LLM、Neo4j、PostgreSQL、Milvus 或模型服务。
- [x] 不执行 Git 提交、推送、重置或提交演示运行生成的数据。
