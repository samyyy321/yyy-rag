# YYY-RAG 项目说明书

- 文档版本：2026-09-15
- 项目类型：文档 RAG、GraphRAG、NL2SQL、多通道融合问答与 TruLens 评测系统
- 运行环境：Conda `yyy-rag`
- 后端框架：FastAPI
- 前端框架：React + Vite + TypeScript
- 主要存储：PostgreSQL、MinIO、Milvus、Neo4j
- 模型服务：兼容 OpenAI 接口的 DashScope 配置

## 1. 项目定位

YYY-RAG 提供两类相互独立又可融合的能力：

1. **知识库管理**：用户创建知识库、上传文档，系统异步解析、切块、向量化并写入 Milvus；
2. **统一智能问答**：用户在单一聊天页面中选择文档知识库、医学知识图谱、运营数据库一个或多个通道，系统执行单通道回答或多通道融合。

系统中的 Neo4j 图谱和运营数据库表当前由演示脚本初始化，主要用于验证 GraphRAG、NL2SQL、只读查询限制和多通道融合流程。演示图谱不构成医疗诊断、处方、治疗或健康建议依据。

## 2. 核心能力

### 2.1 知识库与文档

- 知识库 CRUD、分页查询；
- PDF、DOCX、TXT、Markdown 单文件上传；
- MinIO 保存原始文档；
- PostgreSQL 保存知识库、文档和导入任务元数据；
- BackgroundTasks 执行异步导入；
- MinerU 优先解析，失败时回退 LlamaIndex；
- DashScope Embedding、Milvus 向量检索、Rerank 和 HyDE。

### 2.2 统一智能问答通道

| 通道 | 标识 | 数据来源 | 是否要求知识库 |
|---|---|---|---|
| 文档检索 | `document` | 当前知识库的 Milvus 文档向量 | 是 |
| 图谱检索 | `graph` | Neo4j 医学知识图谱 | 否 |
| 运营数据检索 | `sql` | PostgreSQL 运营演示表 | 否 |

Chat 请求可选择一个或多个通道。多通道使用 `asyncio.gather(return_exceptions=True)` 并行收集证据；单个通道失败不会阻塞其他通道。成功证据超过一个时通过融合提示词生成最终回答。

### 2.3 流式输出

`POST /api/v1/chat/stream` 使用 Server-Sent Events 返回模型文本分片。前端按照到达顺序追加到助手消息中。

### 2.4 回答来源与展示

文档通道的模型上下文保留文档名称，回答可使用：

```text
【来源：文档名称】
```

页码、页码未知、分块序号和相似度不出现在回答正文。前端安全解析回答中的 `**加粗**` 为粗体，但不会把模型内容当作 HTML 执行。

## 3. 总体架构

```text
React 前端
  ├── 知识库管理视图
  │     └── FastAPI 知识库 / 文档 API
  └── 统一智能问答视图
        └── FastAPI Chat / Chat Stream
              ├── document -> PostgreSQL 校验 -> Embedding / Milvus / Rerank
              ├── graph    -> 实体抽取 -> NL2Cypher -> Neo4j
              ├── sql      -> NL2SQL -> PostgreSQL 运营演示表
              └── 多通道   -> asyncio.gather -> 融合提示词
```

文档导入链路：

```text
上传文件
  -> MinIO 保存原文件
  -> PostgreSQL 创建文档和导入任务
  -> BackgroundTasks 认领任务
  -> MinerU 或 LlamaIndex 解析
  -> 切块、Embedding
  -> Milvus 写入
  -> 更新文档和任务状态
```

## 5. Chat API 契约

### 5.1 请求字段

```json
{
  "question": "用户问题",
  "role": "patient",
  "top_k": 20,
  "rerank_top_k": 5,
  "use_hyde": true,
  "channels": ["document", "graph", "sql"],
  "knowledge_base_id": "知识库 UUID"
}
```

字段说明：

- `channels` 可取 `document`、`graph`、`sql`，必须非空且不可重复；
- 未传 `channels` 时默认 `['document']`；
- `knowledge_base_id` 仅在 `channels` 包含 `document` 时必填；
- 纯 graph、纯 sql 或 graph + sql 请求不能依赖知识库；
- `top_k`、`rerank_top_k`、`use_hyde` 仅对 document 通道有检索意义，前端只在选择 document 时显示这些设置；
- `role` 对所有通道生效。

### 5.2 非流式接口

```text
POST /api/v1/chat
```

返回完整回答。只有 document 通道会填充兼容的 `sources` 字段；纯 graph/sql 返回空来源列表。

### 5.3 SSE 流式接口

```text
POST /api/v1/chat/stream
```

每个事件格式：

```text
data: {"content":"一个回答文本片段"}
```

## 6. 查询安全边界

### 6.1 Cypher

GraphRAG 生成的 Cypher 必须：

- 以 `MATCH` 或 `OPTIONAL MATCH` 开始；
- 包含 `RETURN`；
- 只有一条语句；
- 未设置 LIMIT 时自动补 `LIMIT 20`；
- 显式 LIMIT 不得超过 20；
- 不含 `CREATE`、`MERGE`、`DELETE`、`SET`、`REMOVE`、`CALL`、`LOAD CSV`、`FOREACH`。

### 6.2 SQL

NL2SQL 生成的 SQL 必须：

- 只允许单条 `SELECT`；
- 只能访问 `categories`、`products`、`customers`、`orders`、`order_items`；
- 未设置 LIMIT 时自动补 `LIMIT 100`；
- 显式 LIMIT 不得超过 100；
- 禁止 INSERT、UPDATE、DELETE、DROP、ALTER、CREATE、权限和导入类关键字。

GraphRAG 与 NL2SQL 在提示词生成、查询校验或查询执行失败时各最多执行两次完整尝试，不做复杂退避。

## 8. 初始化演示数据

### 8.1 NL2SQL 运营演示表

```powershell
conda run --no-capture-output -n yyy-rag python -m scripts.init_operational_tables
```

脚本使用 `CREATE TABLE IF NOT EXISTS` 创建五张运营表，并使用 `ON CONFLICT DO NOTHING` 写入少量演示分类、商品、客户、订单和订单明细。重复运行不会删除或重复写入已有演示主键记录。

### 8.2 GraphRAG Neo4j 演示图谱

```powershell
conda run --no-capture-output -n yyy-rag python -m scripts.init_medical_graph
```

脚本使用 `utf-8-sig` 读取 JSON，因此兼容普通 UTF-8 和 PowerShell 可能写入的 UTF-8 BOM。脚本创建节点名称唯一约束，并以参数化 `MERGE` 写入演示节点和关系。

演示数据限制：

- 数据只用于验证 GraphRAG、NL2SQL、融合和界面流程；
- 不代表真实临床知识；
- 不得将演示疾病、药物、症状、饮食或关系用于医疗诊断、治疗或处方。

## 9. 前端行为

前端有两个顶层视图：

1. **知识库管理**：知识库列表、创建、编辑、删除、文档上传、导入状态和文档删除；
2. **智能问答**：唯一聊天界面，选择通道、条件选择知识库、显示流式回答。

智能问答的高级设置规则：

| 当前通道 | 可见高级设置 |
|---|---|
| 包含 document | 回答角色、粗检索数量、重排数量、HyDE |
| 仅 graph / sql | 仅回答角色 |

聊天回答中的 `**文本**` 会安全显示为粗体；前端不解析或执行模型提供的 HTML。

## 11. 健康检查边界

```text
GET /api/v1/health
```

当前健康检查验证 PostgreSQL、MinIO 和 Milvus 的连通性。它不代表 Neo4j、运营演示表或模型服务一定可用。纯 graph/sql 请求按通道延迟加载文档依赖，不会因为请求本身而初始化 Milvus 或 Embedding；但若调用健康检查，Milvus 不可用仍会导致健康状态不可用。

## 13. 已知限制

- GraphRAG 使用演示图谱，不自动从上传文档抽取或更新图谱；
- NL2SQL 仅查询五张运营演示表，不访问知识库业务表；
- 文档导入任务在 API 进程内执行，不是持久化任务队列；
- 上传接口当前会把整个文件读入内存；
- Chat 健康检查不覆盖 Neo4j、演示运营表和 LLM；
- 多通道失败容忍仅保留成功证据，不提供复杂重试退避、缓存或审计。
